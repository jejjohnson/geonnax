    Bases¶

    The bases geonnax used to hold now live in functax, which geonnax depends on (jejjohnson/geonnax#153). geonnax keeps the networks and imports functax for the maths, so there is one copy of each basis in the stack.

    Where each basis went¶

    The names did not change, only their module:

    • functax.basis.fourier: the box eigenpairs fourier_basis, fourier_basis_1d, fourier_eigenvalues and fourier_eigenvalues_1d, with Dirichlet, Neumann or periodic boundaries.
    • functax.basis.vector: the divergence-free and curl-free box bases divfree_basis and curlfree_basis.
    • functax.basis.sphere: real_spherical_harmonics, harmonic_degrees, vector_spherical_harmonics, the needlets (needlet_basis, needlet_window) and shell_basis.
    • functax.basis.slepian: the cap, polar-gap and region Slepian bases, SlepianBasis, SlepianCapBasis, shannon_number and spherical_polygon_mask.
    • functax.basis.local: rbf_basis, spherical_rbf_basis, the Wendland kernels, the Gabor frames and the DWT matrices wavelet_basis_1d and wavelet_basis_2d.
    • functax.basis.eigen: eof_basis, graph_laplacian_eigpairs and cotangent_laplacian_eigpairs.
    • functax.basis.polynomial: legendre_polynomials, associated_legendre and associated_legendre_indices.
    • functax.basis.features: fourier_features, seasonal_features, seasonal_frequencies, gaussian_window_features, and the random Fourier feature maps rff_forward and rff_cosine_forward.
    • functax.geometry: the sphere grids (fibonacci_sphere, gauss_legendre_grid, latlon_grid, healpix_grid), icosphere and mesh_vertex_areas.
    • functax.quad: gauss_legendre, which returns a Rule that unpacks to (nodes, weights).

    Deprecated paths¶

    Every moved name still resolves from geonnax.basis until geonnax 0.0.13, and emits a DeprecationWarning naming its functax path. The sphere grids and spherical_polygon_mask keep geonnax's defaults there (radians for grid output, degrees for polygon vertices). functax takes an explicit unit= with no default, so a caller who relied on a default gets an error instead of wrong numbers.

    What stays in geonnax¶

    The feature-engineering helpers stay here: interaction_features (products of selected column pairs) and standardize / unstandardize (an affine map with a precomputed mean and standard deviation).

    basis ¶

    Feature engineering helpers, and the old home of the bases now in functax.

    geonnax's bases moved to functax (jejjohnson/geonnax#153): the eigenfunction, localized and frame bases to the family submodules of functax.basis, the sphere grids and meshes to functax.geometry, and gauss_legendre to functax.quad. Their names still resolve here for one release, with a DeprecationWarning naming the functax path; see the _MOVED table.

    The feature-engineering helpers stay in geonnax:

    • interaction_features — element-wise products on selected pairs of input columns.
    • standardize / unstandardize — affine transform with a precomputed mean and std.

    def interaction_features(
    x: Float[Array, "N D"],
    pairs: Int[Array, "K 2"],
) -> Float[Array, "N K"]:
    r"""Element-wise products on selected pairs of input columns.

    For each pair $(i, j)$ and each row $n$, computes
    $x_{n, i} \cdot x_{n, j}$.

    Args:
        x: Input matrix, shape ``(N, D)``.
        pairs: Index pairs, shape ``(K, 2)``. Empty pairs yield an
            ``(N, 0)`` output.

    Returns:
        Array of shape ``(N, K)`` of pairwise products.

    Examples:
        >>> import jax.numpy as jnp
        >>> from geonnax.basis import interaction_features
        >>> x = jnp.arange(6.0).reshape(2, 3)  # (N=2, D=3)
        >>> pairs = jnp.array([[0, 1], [0, 2]])  # (K=2, 2)
        >>> interaction_features(x, pairs).shape
        (2, 2)
    """
    if pairs.shape[0] == 0:
        return jnp.zeros((x.shape[0], 0), dtype=x.dtype)
    # x[:, pairs] has shape (N, K, 2); reduce the paired axis with prod.
    selected = x[:, pairs]
    return einx.prod("n k [two]", selected)

    def standardize(
    x: Float[Array, "*shape"],
    mu: Float[Array, "*shape"],
    std: Float[Array, "*shape"],
) -> Float[Array, "*shape"]:
    """Affine standardize: ``(x - mu) / std``.

    Broadcasts ``mu`` and ``std`` against ``x`` per the JAX broadcasting
    rules. ``std`` is *not* clamped; pass a positive value or guard
    upstream.

    Examples:
        >>> import jax.numpy as jnp
        >>> from geonnax.basis import standardize
        >>> x = jnp.array([1.0, 3.0, 5.0])
        >>> bool(jnp.allclose(standardize(x, 3.0, 2.0), jnp.array([-1, 0, 1])))
        True
    """
    return (x - mu) / std

    def unstandardize(
    z: Float[Array, "*shape"],
    mu: Float[Array, "*shape"],
    std: Float[Array, "*shape"],
) -> Float[Array, "*shape"]:
    """Inverse of `standardize`: ``z * std + mu``.

    Examples:
        >>> import jax.numpy as jnp
        >>> from geonnax.basis import standardize, unstandardize
        >>> x = jnp.array([1.0, 3.0, 5.0])
        >>> # unstandardize undoes standardize for the same (mu, std).
        >>> z = standardize(x, 3.0, 2.0)
        >>> bool(jnp.allclose(unstandardize(z, 3.0, 2.0), x))
        True
    """
    return z * std + mu
